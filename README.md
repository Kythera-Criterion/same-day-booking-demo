# 当日予約デモ（Next.js + Supabase）

「今日、今から行ける枠」をサロンが出し、利用者がその場で予約する仕組みの、裏側の動きを確かめるためのデモです。
画面は最小限にし、次の3点が実際に動くことを示すことを目的にしています。

1. **サロンが空き枠を出すと、利用者の画面にすぐ表示される**（リアルタイム反映）
2. **同じ枠に同時に予約が来ても、成立するのは1件だけ**（行ロックと一意制約の二重の防止）
3. **サロンAの予約はサロンBから見えない、利用者は自分の予約しか見えない**（データベース側の行単位のアクセス制御）

店名・住所・人物名はすべて架空です。特定のサービスのロゴ、画面、コードは使っていません。

---

## 構成

- 画面：Next.js（App Router / TypeScript）
- データベース・ログイン：Supabase（PostgreSQL）
- 予約の作成や状態の変更は、すべてデータベースの関数（`book_slot` など）経由で行います。画面側からテーブルへ直接書き込む権限は与えていません。
- 現在地は利用者の端末の中だけで距離の計算に使い、サーバーへは送りません。

```
supabase/
  migrations/0001_init.sql   テーブル・関数・アクセス制御（RLS）
  seed.sql                   デモ用のサロン・美容師・メニュー
  demo_slots.sql             録画の直前に、今日の空き枠を用意する
app/
  page.tsx                   利用者の画面（時間帯を選ぶ → 近い順に最大3件 → 予約）
  salon/page.tsx             サロンの画面（メニューと時刻を選んで枠を出す・予約の確認）
scripts/
  setup-demo.mjs             デモ用アカウントの作成
  race-test.mjs              10件の同時予約で、成立が1件だけになることの確認
  rls-check.mjs              権限の分離の確認（8項目）
tests/local/                 ローカルのPostgreSQLでの動作確認（結果例：result_example.txt）
docs/screens/                画面イメージ
```

## データベースで守っているルール

- 予約できるのは、今日の枠で、開始10分前まで
- サロンが枠を出せるのは、今日の9時以降の時刻で、今から10分以上先
- 同じ美容師の枠は、時間が重ならない
- サロンが受け付ける性別の条件に合わない予約は受け付けない（性別そのものはサロンに渡さない）
- 無断キャンセルは予約時刻を過ぎてから記録でき、直近90日で2回になると新しい予約を受け付けない
- サロン都合のキャンセルは無断キャンセルとして記録せず、時間が残っていれば枠を戻す
- サロンや運営の操作は記録を残す

## 動かし方

必要なもの：Node.js 20.6以上、Supabase のアカウント（無料プランで可）

### 1. Supabase のプロジェクトを作る

Supabase で新しいプロジェクトを作成します（リージョンは Tokyo を推奨）。

### 2. データベースを作る

Supabase の **SQL Editor** で、次の2つを順に実行します。

1. `supabase/migrations/0001_init.sql`
2. `supabase/seed.sql`

### 3. 接続情報を設定する

`.env.example` をコピーして `.env.local` を作り、**Project Settings → API** の値を入れます。

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...   ← アカウント作成と確認スクリプトだけで使用。公開しないでください
DEMO_PASSWORD=demo-pass-2026
```

### 4. インストールとデモ用アカウントの作成

```bash
npm install
npm run setup:demo
```

次のアカウントが作られます（パスワードは `DEMO_PASSWORD`）。

| 用途 | メールアドレス |
|---|---|
| サロンA（HAIR ROOM AOI）のスタッフ | salon-a@demo.test |
| サロンB（atelier nagi）のスタッフ | salon-b@demo.test |
| 利用者1（山田 花子・女性） | user1@demo.test |
| 利用者2（鈴木 一郎・男性） | user2@demo.test |

### 5. 今日の空き枠を用意する

SQL Editor で `supabase/demo_slots.sql` を実行します。
今日の枠しか作れないため、**日本時間の9時〜21時ごろ**に実行してください。

### 6. 起動する

```bash
npm run dev
```

- 利用者の画面：http://localhost:3000
- サロンの画面：http://localhost:3000/salon

ログインはタブごとに分かれるので、同じブラウザで利用者とサロンを並べて使えます。

### 7. 同時予約と権限の確認

```bash
npm run test:race   # 10件の同時予約 → 成立は1件だけ
npm run test:rls    # 権限の分離を8項目で確認
```

ローカルの PostgreSQL（16以上）がある場合は、Supabase を使わずにデータベース部分だけを確認できます。

```bash
PSQL="psql -h localhost -p 5432 -U postgres" ./tests/local/run.sh
```

## 録画の手順（約90秒）

画面の左に利用者の画面（スマホ幅）、右にサロンの画面を並べ、下にターミナルを開いておきます。
録画の直前に `demo_slots.sql` を実行してください。

| 時間 | 操作 | 見せたいこと |
|---|---|---|
| 0〜20秒 | サロンの画面でメニューと時刻を選び、「この枠を出す」を押す | 3回のタップで公開でき、利用者の画面にすぐ表示される |
| 20〜40秒 | 利用者の画面で、出た枠の「予約」を押す | 予約が確定し、サロンの画面に「新しい予約が入りました」と即座に出る |
| 40〜60秒 | ターミナルで `npm run test:race` | 10件同時に予約しても、成立は1件だけ |
| 60〜80秒 | ターミナルで `npm run test:rls` | サロン同士・利用者同士で情報が見えないことを8項目で確認 |
| 80〜90秒 | `supabase/migrations/0001_init.sql` の `book_slot` と RLS の部分を表示 | 仕組みをデータベース側で守っていること |

## 本番に向けて残っていること

このデモは裏側の要点を確かめるためのもので、次の機能は含んでいません。

- LINE・メールでの通知、ブラウザへの通知
- 新規登録画面（デモではスクリプトでアカウントを作成）
- 運営用の画面（サロンの承認、問い合わせ、実証の集計）
- ヘア写真の保存と共有、カルテ、予約後のアンケート
- 実証終了時のデータ削除や、正式サービスへの移行の仕組み
